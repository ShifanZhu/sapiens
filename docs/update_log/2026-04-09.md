## LiDAR-HMR CUDA + Sapiens depth fusion smoke (Blackwell)

### New / updated

- `scripts/smoke_lidar_hmr_depth_vit.py` — end-to-end: LiDAR-HMR `pose_meshgraphormer` forward (random 1024×3 PCD) → `vert_feat` `.npy` → `convert_lidar_hmr_vert_feat.py` → `VisionTransformerWithDepth` + `ImageClassifier` one optimizer step + `predict`. Uses filenames **without** a stem ending in `_rgb` so `load_depth_embedding`’s `_rgb` strip does not hide the depth file (see backbone docstring).
- `pretrain/mmpretrain/models/classifiers/image.py` — `loss` / `predict` / `forward(mode=tensor)` pass `image_names` from `DataSample.metainfo['img_path']` when **every** sample has it, so disk `depth_embed_path` works in real training loops.
- `scripts/setup_lidar_hmr.sh` — pointers to cu128 / smoke script and converter.
- `third_party/PointTransformerV2` — cloned for `libs/pointops`; `libs/pointops/setup.py` adds `--allow-unsupported-compiler` for nvcc on newer host GCC; **`ln -s functions pointops`** under `libs/pointops` so `import pointops` works without a pip install.
- `third_party/LiDAR-HMR/models/smpl_hybrik/SMPL.py` — optional `kornia.geometry.conversions.rotation_matrix_to_axis_angle` if `pytorch3d` missing.
- `third_party/LiDAR-HMR/models/pose_mesh_net.py` — lazy-import `Regressor` inside `LiDARCap_` (avoids `pointnet2_ops` for `pose_meshgraphormer`); `up1` input dim uses `self.graphs[2].shape[0]` (SMPL graph level size vs shipped hardcoded 1946).
- `third_party/LiDAR-HMR/models/data/J_regressor_h36m_correct.npy` — fetched from Pose2Mesh_RELEASE; `models/graphormer/data/J_regressor_extra.npy` from MeshGraphormer (SMPL pickle was already present in tree).

### Environment used on this machine

- Conda env **`lidar_smoke`** (Python 3.10): `torch==2.11.0+cu128`, `torchvision`, `torchaudio`, `conda install -c nvidia cuda-nvcc=12.8 cuda-toolkit=12.8 libcusparse-dev`, `pip install mmengine`, `mmcv==2.2.0` from OpenMMLab wheels (`cu121/torch2.4.0` index), `pip install -e pretrain/`, PyG scatter/cluster/sparse (PyG wheel index `torch-2.11.0+cu128`), `torch-geometric`, `kornia`, LiDAR-HMR-light deps (`fvcore`, `easydict`, `timm`, `smplx`, `boto3`, …), `conda-forge::chumpy`.

### Commands that succeeded

```bash
conda activate lidar_smoke
export CUDA_HOME="$CONDA_PREFIX"
export PYTHONPATH="/path/to/sapiens/third_party/PointTransformerV2/libs/pointops:/path/to/sapiens/third_party/LiDAR-HMR"
cd /path/to/sapiens && python scripts/smoke_lidar_hmr_depth_vit.py
```

Optional: `--skip-lidar-hmr` if `tmp_lidar_hmr_smoke/vert_feat/lidar_smoke.npy` already exists.

## BEDLAM2 demo (`demo_bedlam2.py`)

### Change

- `pose/demo/demo_bedlam2.py` — added `--max-seqs` (forwards to `Bedlam2Dataset.max_seqs`). Scanning the full `test_seqs.txt` list opens every label NPZ during indexing and can take many minutes with no progress output; limiting sequences makes the demo practical.

### Verified

- `python demo/demo_bedlam2.py` with `--max-seqs 24`, checkpoint `Outputs/train/bedlam2/run_full_20260409_215724/best_mpjpe_body_val_epoch_1.pth`, `--num-samples 48` → **48 PNGs** under `pose/Outputs/demo/bedlam2/run_full_20260409/` (~42s on this machine).
